# 主办方后台完整操作指南

访问入口：`/admin`

## 这份指南怎么用

主控后台是婚礼游戏的最高权限操作台。本指南从婚礼前配置和彩排清场开始，覆盖当天开场、九个婚礼状态、任务审核、第二轮派发、团队结算、线索、投票、揭晓、颁奖、备份和故障恢复。

所有修改都会写入审计记录。管理员密码、邀请码、宾客密码、隐藏身份和秘密任务不得出现在投屏、群聊或公开截图中。婚礼当天不要直接修改数据库、运行 seed、覆盖名单或清空生产数据。

## 工作人员权限边界

1. **主控后台 `/admin`**：宾客管理、流程控制、任务与线索配置、奖项、数据导出、密码更换和彩排清场。
2. **主持人台 `/host`**：私密全员总览、团队/个人现场加分、流程切换和终局操作。
3. **任务站 `/station`**：核对任务证据、通过或退回任务、现场补充验证照片。
4. **公开结果 `/scoreboard`**：只显示允许公开的团队成绩、身份揭晓、奖项和最终排名，不包含秘密任务答案。

主控不要把 `/admin` 页面投屏。需要对宾客展示时，只打开公开结果页。

## 后台四个主入口

1. **开场与宾客**：系统状态、开场检查、注册进度、自拍与抽卡进度、宾客资料和密码重置。
2. **现场执行**：流程控制、任务审核、宾客临时提示、大屏内容和团队挑战计分。
3. **终局结算**：奖项、团队结算与线索、投票、身份揭晓、排名和积分流水。
4. **婚礼设置**：任务、角色预设、团队线索、奖项配置、管理员密码、数据导出和彩排清场。

占空间较大的配置区默认折叠。只在操作时展开，完成后收起，避免手机误触。

## 婚礼前 7 天：正式配置

1. 关闭注册，确认 34 位宾客、33 个登录账号的正式名单、中文和英文姓名、桌号、是否使用软件及排序正确；陈天然与陈子宥应只显示为一个联合账号。
2. 核对家人组、海岛组和沙漠组；家人组不进入团队排名，但仍可获得个人积分。
3. 检查第一轮正式任务容量、固定仪式角色、两队随机恶作剧者池、爱心与星星配对人数。
4. 确认任务积分、核验要求和任务机制正确；已经抽卡后不要停用相关任务或更改容量。
5. 设置正式共享邀请码。保存后系统不会回显原文，应由主办方安全保存。
6. 为海岛组和沙漠组分别准备至少 2 条可启用的团队线索；不要保留默认、空白或未指定队伍的占位线索。
7. 配置需要公开的奖项名称，但可以等婚礼当天再填写获奖对象与颁奖词。
8. 在 iPhone Safari、安卓 Chrome 和微信内置浏览器完成一次注册、自拍、抽卡、提交和重复登录测试。

完成标志：“开场检查”的核心项目全部通过，不存在会阻塞抽卡或第二轮派发的红色项目。

## 彩排结束后的正式清场

彩排清场不可从网页撤销，只能用于正式婚礼开始前清除彩排运行数据。

1. 关闭注册、投票和公开大屏。
2. 导出宾客、任务、个人积分、团队积分、竞拍金币、奖项和审计七类 CSV，并保存在两处。
3. 在清场预览中核对已认领宾客、任务、投票、自拍和验证照片数量。
4. 勾选备份确认、填写清场原因，并输入页面要求的确认短语。
5. 在第二个确认卡再次核对影响范围后执行。
6. 若提示照片仍待删除，保持确认信息不变，点击“重试照片清理”直到完成。
7. 清场后用一位测试宾客登录，确认需要重新设置密码和自拍；随后退出并再次清理这条测试运行数据。

清场保留：正式名单、锁定队伍与初始身份、任务、线索、奖项名称、实体卡配置和审计记录。

清场删除：宾客密码与会话、自拍、抽卡、任务进度、验证照片、投票、个人与团队积分、关系配对和第二轮运行状态。

## 婚礼当天开场前 60 分钟

1. 登录后台，确认数据库在线、部署版本和最近同步时间正常。
2. 确认当前环节是“宾客签到”，注册开放，投票关闭，身份结果隐藏。
3. 展开“开场检查”，处理所有红色或橙色项目。
4. 在宾客管理核对已认领、已上传头像、已抽卡和尚未注册人数；进度必须来自真实运行数据，不应固定显示全员完成。
5. 用备用手机完整走一次邀请码、姓名、四位密码、自拍、抽卡和进入主页。
6. 登录主持人台和任务站，确认三端显示同一婚礼环节。
7. 打开公开结果页；未开放时应显示等待状态，不能提前泄露个人排名或身份。
8. 准备备用热点和纸质计分表，但不要提前打开彩排清场模块。

## 完整流程总览

1. 宾客签到 - 第一轮任务领取
2. 等待仪式 - 第一轮任务进行中
3. 婚礼仪式 - 第一轮任务暂停
4. 仪式结束 - 第一轮任务恢复
5. 婚宴前奏 - 第二轮任务发放
6. 婚宴开始 - 第二轮任务进行中
7. 婚宴互动 - 团队挑战
8. 最终投票 - 恶作剧者指认
9. 身份揭晓与颁奖 - 最终积分结算

前七个状态从“现场执行 - 流程控制”推进。投票、关闭投票和公布身份必须在“终局结算”或主持人台使用专用按钮完成。

## 环节一：宾客签到

### 后台操作

1. 保持阶段为“宾客签到”，开放注册。
2. 在宾客管理观察已认领、头像和抽卡进度。
3. 宾客忘记密码时，核对本人后使用“重置密码”；该宾客旧会话会全部退出。
4. 宾客选错姓名时，立即停止其继续操作，由主控重置错误认领。
5. 需要新增迟到宾客时，在名单资料区新增后重新核对任务与队伍容量。

### 宾客手机应显示

- 共享邀请码入口和姓名列表；
- 首次设置四位密码；
- 圆形婚礼自拍；
- 抽卡与身份隐私提示；
- 随机四位玩家编号。

### 完成检查

- 计划参与第一轮的宾客均已抽卡；
- 头像数量与实际完成自拍人数一致；
- 固定仪式角色抽到指定任务；
- 两队没有出现重复恶作剧者预设。

## 环节二：等待仪式与第一轮执行

### 流程切换

1. 在“现场执行 - 流程控制”选择“等待仪式”。
2. 阅读确认卡，确认影响范围后执行。
3. 切换成功后页面应显示“第一轮任务进行中”。

### 任务审核

1. 任务站打开待审核宾客，核对姓名、任务标题、完成说明、核验要求和可选照片。
2. 符合要求时点击“通过并加分”；任务预设分值进入个人积分流水。
3. 不符合时填写宾客可理解的具体原因，再点击退回。
4. 任务成功处理后应立即离开待审核队列；页面报错时保留错误，不要重复点击或另外补分。
5. 前 3 位完成首轮任务的宾客各自动获得额外 1 分；这里不会派发升级任务或秘密线索。

### 配对与编号

- 爱心、星星和恶作剧者确认都在对应任务内完成；
- 一方发送邀请后，另一方可直接接受，不需要再次输入对方编号；
- 编号输入错误提示应出现在输入框附近；
- 查询列表只显示姓名、头像和编号，不公开队伍、身份或任务；
- 连续错误会触发限制，主控不要帮助宾客猜号。

## 环节三：婚礼仪式

1. 切换到“婚礼仪式”。
2. 确认宾客页面显示第一轮任务暂停，上传、提交和配对按钮禁用。
3. 仪式进行中不要审核需要宾客继续操作的任务，也不要发布会诱导宾客看手机的临时提示。
4. 当前状态应在主控、主持人和任务站同步显示。

### 异常判断

如果有人仍能提交，先记录页面和时间，不要修改数据库；刷新三端状态并检查部署版本。

## 环节四：仪式结束

1. 切换到“仪式结束”。
2. 确认第一轮任务提交、照片和伙伴确认已经恢复。
3. 明确告诉主持人：此阶段不会派发第二轮任务。
4. 在进入婚宴前奏前，核对未完成的爱心、星星和恶作剧者邀请。
5. 如配对人数不完整，系统会在第二轮切换时自动处理允许的最终匹配；存在未解决邀请时会阻止切换并给出错误。

## 环节五：婚宴前奏与第二轮派发

### 切换前检查

1. 20 位竞技玩家均已完成抽卡。
2. 海岛组与沙漠组各有且只有 1 名恶作剧者。
3. 爱心和星星配对状态满足系统要求。
4. 固定致辞、戒指和应援角色没有占用冲突身份。
5. 第二轮任务池已启用，固定和随机分配容量可覆盖全部竞技玩家。

### 执行

1. 选择“婚宴前奏”，阅读确认卡。
2. 点击确认后，系统会先完成第一轮关系结算，再一次性创建第二轮任务。
3. 操作成功后应看到 `phase_one_completed_at` 对应的已完成状态，以及宾客端“新的命运”弹窗。
4. 丘比特幸运星会立即把第一轮积分翻倍并标记能力完成；不要手工重复加分。
5. 领航星和孤单丘比特只会分配给相应图案中最终未配对的玩家，并显示获得能力的背景说明。

### 失败处理

切换失败不会部分派卡，流程仍停留在“仪式结束”。完整保留红色错误提示，按提示补齐抽卡、配对、角色来源或任务容量后再重试。不要跳到婚宴开始，也不要连续点击确认。

## 环节六：婚宴开始

1. 切换到“婚宴开始”。
2. 该操作只开放第二轮行动，不会重复派发任务。
3. 确认宾客可查看晚宴菜单，菜单图片清晰且可放大阅读。
4. 检查爱心与星星升级任务包含背景说明、秘密选择要求和完整积分表。
5. 检查恶作剧者伪装界面与普通宾客一致；只有主动展开真实界面后才显示真正任务。
6. 临时提示只能填写全员可以看到的信息，结束后及时清空。

## 环节七：婚宴互动与团队挑战

### 流程和计分

1. 切换到“婚宴互动”。
2. 按现场游戏逐轮记录海岛组或沙漠组团队分，每条流水必须有原因。
3. 个人临时奖励使用个人积分功能，核对头像与姓名后记录。
4. 家人可参与互动并获得个人积分，但不创建家人组团队分。
5. 任务个人分、投票奖励和丘比特幸运星翻倍都不加入团队挑战分。

### 线索准备

1. 打开“婚礼设置 - 团队线索库”。
2. 每条线索必须指定海岛组或沙漠组、分类、名称和内容。
3. 两队各至少准备 2 条启用线索。
4. 删除或停用空白、默认和不准备现场使用的线索。
5. 身份答案不要直接写进公开提示或大屏内容。

## 团队积分结算并发放线索

1. 在终局结算确认当前阶段是“婚宴互动”。
2. 核对两队团队积分流水和最终合计。
3. 确认每队至少 2 条启用线索。
4. 点击“结算团队积分并发放线索”，再次核对确认卡中的分数。
5. 系统保存团队分冻结快照，并按排名把线索发给所有已抽卡的第二轮队员，包括恶作剧者和剧情角色。
6. 第一名每人获得 2 条，第二名每人 1 条；并列第一时两队各 2 条。
7. 结算后团队加分应锁定。后续个人任务、投票和揭晓不会改变冻结快照。

完成检查：宾客端出现团队线索，主控和主持人显示团队线索已结算，团队分与结算前完全一致。

## 环节八：最终投票

### 投票前

1. 给宾客足够时间阅读团队线索。
2. 核对需要公开的奖项名称、获奖对象和颁奖词，但暂不公布身份结果。
3. 确认注册可以关闭，现场不再有首次登录宾客。

### 开启与关闭

1. 点击“开启新一轮最终投票”；系统关闭注册并创建新轮次。
2. 身份揭晓前后台只显示已提交人数，不显示候选人实时票数。
3. 每位宾客每轮只能提交一次，提交后不可修改。
4. 完成真正任务的恶作剧者额外一票必须由后端实际保存为 2 票，不能只显示提示文案。
5. 确认现场参与人数后点击“关闭本轮投票”。
6. 若必须重投，应开启新轮次；不要删除或覆盖历史投票。

## 环节九：身份揭晓、最终积分与奖项

### 公布与结算

1. 确认投票已关闭，奖项内容已保存。
2. 点击“公布身份并结算个人奖励”；团队挑战分不会在此步骤改变。
3. 系统公开两名恶作剧者、是否逃脱、每位候选人的获票数和实名投票来源。
4. 投中本队恶作剧者的玩家自动获得 2 点个人积分；同一轮重复刷新不会重复加分。
5. 完整个人排名包含家人；未被识破的恶作剧者按荣誉规则置顶，但原始积分不被篡改。
6. 团队排名只包含海岛组和沙漠组，并使用之前冻结的团队分。

### 奖项和公开结果

1. 只有勾选随身份揭晓公布的奖项才会显示在公开结果页。
2. 核对奖项对象、颁奖词和最终个人排名。
3. 按现场需要开放公开大屏；不得把主控或主持人私密页面投屏。
4. 如果临时隐藏公开结果，已经结算的积分不会撤销。

## 婚礼结束后的数据收场

1. 导出宾客、任务、个人积分、团队积分、竞拍金币、奖项和审计记录。
2. 确认导出文件可打开、行数合理，并保存到两个独立位置。
3. 关闭注册、投票和公开大屏。
4. 主控、主持人和任务站依次点击“安全退出”。
5. 保留正式婚礼数据和审计记录；不要执行彩排清场。
6. 记录任何离线补录、人工纠分或现场异常，便于之后复核。

## 常见故障与恢复

- **页面没有更新**：先确认网络和最近同步时间，再刷新一次；不要连续提交。
- **宾客忘记密码**：核对本人后重置；该宾客所有旧会话会退出。
- **任务审核失败**：保留错误，确认任务仍为待审核后再试；不要额外手工加同样分数。
- **第二轮切换失败**：按错误提示核对 20 位竞技玩家、两队恶作剧者、爱心/星星配对、固定角色和任务容量。
- **团队结算按钮不可用**：确认阶段为婚宴互动、两队都有团队成绩、每队至少 2 条启用线索。
- **线索未到账**：确认该宾客已抽卡且进入第二轮队伍，检查团队线索结算状态；不要逐人重复手工发放同一线索。
- **团队分在投票后变化**：立即停止揭晓流程，核对冻结快照和团队积分流水；不要用个人加分修正团队分。
- **大面积断网**：停止新抽卡、提交、计分和投票，使用纸质记录；恢复后按时间顺序补录并注明“现场离线补录”。
- **后台会话失效**：重新登录后先核对阶段和最近操作审计，再继续；不要假设上一次点击已成功。
- **生产服务异常**：不要重置或重新 seed 数据；保存纸质记录，服务恢复后统一补录。

## 主控禁止事项

- 不在正式婚礼期间运行彩排清场；
- 不直接修改、清空或重新 seed 生产数据库；
- 不把后台、主持人台或任务站投屏；
- 不公开隐藏身份、秘密任务、答案或实时投票对象；
- 不用重复点击解决延迟；
- 不用无说明的反向加分掩盖误操作；
- 不在投票或揭晓期间重新开放注册；
- 不从普通流程下拉框跳转到最终投票或结果状态。

## 当天结束前最终检查

1. 公开结果页显示正确的恶作剧者、逃脱结果和奖项。
2. 团队分与团队结算前一致，家人组不在团队榜。
3. 完整个人排名包含家人，投票奖励和幸运星翻倍只出现一次。
4. 七类最终 CSV 已导出并双份保存。
5. 注册、投票和公开大屏已关闭。
6. 三个工作人员页面均已安全退出。
