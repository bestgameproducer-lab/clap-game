# Wedding Task MVP

一个适合婚礼现场使用的轻量扫码网页：宾客先输入共享婚礼邀请码，从可搜索的名单中选择姓名，首次进入时自己设置四位密码；随后通过一次性抽卡领取组别、秘密身份和任务。主办方可以控制注册与婚礼阶段、重置密码、审核任务、加分、开放投票和公布结果。

## 已包含

- 宾客首次自设四位密码，之后可跨设备重新登录
- 一次性、均衡分组的秘密身份抽卡
- 默认隐藏身份卡，防止旁人看到屏幕
- 每位宾客只能读取自己的任务与线索
- 任务完成申请
- 宾客可附带完成说明；主办方或任务站核验时必须留下记录，审核通过后自动加分，退回原因会显示给宾客
- 宾客可上传一张压缩后的验证照片；大多数任务将其作为可选证据，`P2-SOCIAL-003` 与 `P2-SOCIAL-004` 则要求先上传再提交。任务站也可在现场替宾客添加、更换或删除照片。照片保存在私有存储中，仅本人和已登录工作人员通过短时链接查看
- 按婚礼阶段开放多轮任务，未来轮次不会提前泄露
- 演示模式可创建和派发自定义任务；正式婚礼模式只执行 21 项版本化 `P1-*`/`P2-*` 任务，后台只读，并由抽卡与婚礼流程自动派发
- 后台可在结算前创建团队线索；线索一旦进入团队结算就锁定内容并保持启用，只能补发已结算给该队的原线索；所有修改都会留下审计记录
- 团队线索按海岛组或沙漠组现场创建；团队挑战结算后才按名次自动发放，任务站只能补发本轮已经结算过的同队线索，绑定与分组信息不会泄露隐藏身份
- 后台人工加减分与不可篡改的积分流水
- 后台预设未抽卡宾客的组别和秘密身份
- 后台可新增、编辑和停用宾客，维护桌号、长辈和仪式任务标记；停用会立即撤销会话且不会删除历史记录
- 32 位宾客、32 个登录账号的三组结构：家人组 10 人、海岛组和沙漠组各 10 名第二轮竞技玩家
- 内置两轮正式任务清单、团队挑战和恶作剧者隐藏剧情；旧升级任务池已经退役
- 正式任务清单确认前使用独立演示任务池；切换正式模式后演示任务不会再被抽中，正式 `P1-*`/`P2-*` 任务只能由抽卡和流程状态机派发
- 正式名单区分任务玩家、荣誉宾客和新人；所有账号都可登录，荣誉宾客与新人看到专属卡片，固定仪式人员通过抽卡动画揭晓指定剧情任务
- 旧“一次性隐藏任务实体卡/隐藏第三名恶作剧者”玩法已经退役；历史迁移和不可逆摘要只为兼容旧审计保留，当前后台、任务站和 API 均不提供生成或兑换入口
- 前 3 位由工作人员核验通过首轮任务的宾客各额外获得 1 点个人积分；配对和能力卡等系统自动完成任务不参与人工核验排名。首轮审核不会发放升级任务或秘密线索，团队线索只在团队挑战显式结算后按名次发放
- 所有主办方修改写入操作审计记录
- 工作人员登录使用数据库中可撤销的哈希会话；后台、主持台和任务站均可安全退出共享设备
- 主办方密码连续输错五次后，服务端会按不可逆设备指纹暂停登录十五分钟；数据库不保存原始 IP、浏览器标识或尝试过的密码
- 最终投票与后台统计
- 最终投票按轮次隔离且每人每轮只能提交一次；公布身份时原子结算猜中恶作剧者的个人奖励，不改动已冻结的团队挑战分
- 婚礼环节使用数据库状态机：后台不能从下拉框绕过投票轮次或终局结算；开启投票会自动关闭注册并清空大屏旧题目；终局一经公布不可撤回，也不能再切回常规环节
- 恶作剧者保留隐藏身份、伪装任务、同伴确认和最终揭晓，不设置独立恶作剧积分，也不参与额外的终局计分
- 投票开关、不可逆的结果公布，以及与结果独立控制的公开大屏开关
- 可由后台单独开放的公开积分大屏，支持团队排名、个人榜与身份揭晓；投影端保留当前标签页最近同步副本并明确标注同步时间
- 旧竞拍金币账本仅为数据库迁移兼容与彩排清场保留，不属于当前主持人流程、后台导出或计分，也不影响个人或团队积分
- 公开大屏严格分开个人积分和团队积分；个人任务分不会重复累加进团队排名
- 正式任务分值由版本化任务清单锁定；任务通过后由系统幂等结算，工作人员不得再手工重复补同一笔分数
- 主办方可以直接编辑公开大屏标题、规则、公开线索和倒计时；私密主持稿由婚礼团队另行保管，不进入精简主持台
- 主办方后台提供 6 项核心开场预检：流程状态、正式邀请码、32 位宾客/32 个账号三组名单、竞技组抽卡容量、第一轮正式任务和固定职务；团队线索在团队结算入口单独校验
- 彩排后可执行受保护的安全清场：必须先关闭所有公开入口、确认八类清场前核对导出并输入固定确认词；这些 CSV 不是包含照片、密码/会话或秘密选择的完整恢复包。系统保留正式名单、任务配置和审计，清除运行数据、整个现场线索库与私密照片，并可安全重试未完成的存储清理
- 团队游戏 5/3/1 分独立流水、主持人控制的公开题目、规则、线索与大屏倒计时
- 独立主持人流程台：查看私密全员总览，使用快问快答、你比划我猜和随机数三个已开放的现场游戏助手，控制婚礼环节、记录个人与团队分数，并完成线索结算、最终投票和揭晓；新人问答等待正式题目后再启用
- 独立现场任务站：按姓名或组别快速查找宾客，现场补拍验证照片、核验任务、补派任务、补发本轮已结算但遗漏的同队线索和调整积分，不显示秘密身份，也不能另选新线索
- 最终奖项配置与公开颁奖区；奖项只有在单项发布且总结果公开后才会出现在大屏
- 投票、关闭和揭晓状态由数据库原子控制，避免投票开放时提前泄露结果
- 宾客页自动同步；弱网时可读取本次会话最近任务，恢复网络后自动刷新
- 首次联网访问后预缓存宾客应用壳和静态资源；断网刷新仍可打开任务页，API 与工作人员页面绝不进入离线缓存
- 公开大屏首次联网后也会准备离线页面壳；数据副本只保留在当前投影标签页，断网时显示 `CACHED` 和最近成功同步时间，不会把旧结果长期留在浏览器中
- 微信与刘海屏兼容：输入控件保持 16px 防止 iPhone 自动放大，页面跟随键盘可视高度，所有宾客和工作人员页面保留顶部、底部安全区；姓名页不会自动弹出键盘
- 切换到其他应用或锁屏时自动遮住秘密身份
- Supabase 云数据库
- 适合部署到 Vercel

## 1. 创建 Supabase 项目

1. 创建一个免费 Supabase 项目。
2. 打开 SQL Editor。
3. 新项目先运行 `supabase/schema.sql`。
4. 按文件名顺序运行 `supabase/migrations` 中尚未应用的迁移。迁移只允许向前执行，不要重复编辑已经上线的迁移文件。
5. 如需本地示例数据，再运行 `supabase/seed-example.sql`。它只创建可重复运行的测试宾客和抽卡兼容任务，不创建会混入现场发放的占位线索；测试宾客仍需首次登录时自行设置四位密码，不能用于正式婚礼名单。
6. 在 Project Settings → API 中复制：
   - Project URL
   - `service_role` key

重要：`service_role` key 只能放在部署平台的服务器环境变量中，绝不能放进浏览器代码或公开仓库。

## 2. 本地运行

```bash
npm install
npm run dev
```

在项目根目录新建仅供本机使用、不会提交到 Git 的 `.env.local`：

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
ADMIN_PASSWORD=请填写至少12位的管理员密码
```

浏览：

- 首页：`http://localhost:3000`
- 商业平台预览：`http://localhost:3000/platform`
- 婚礼方案定制器：`http://localhost:3000/platform/create`
- 宾客页：`http://localhost:3000/guest`
- 后台：`http://localhost:3000/admin`
- 主持人流程台：`http://localhost:3000/host`
- 现场任务站：`http://localhost:3000/station`
- 公开积分大屏：`http://localhost:3000/scoreboard`

登录流程：

- 初始示例邀请码：`LOVE2026`（仅用于本地启动；正式使用前必须在后台更换）
- 邀请码验证通过后才显示可搜索的宾客名单
- 可用中文、拼音或英文名搜索
- 首次选择姓名后自己设置并确认四位密码
- 以后选择相同姓名并输入原密码即可重新登录
- 四位密码只以哈希形式存储在 Supabase
- 同一设备和宾客连续输错五次后暂停登录十五分钟；限流记录只保存不可逆指纹，不保存原始 IP
- 同一客户端连续尝试二十次婚礼邀请码后暂停十五分钟；成功验证会立即清除记录，数据库不保存原始 IP、浏览器标识或尝试过的邀请码
- 后台可把公开示例邀请码轮换为正式共享码；数据库只保存 bcrypt 哈希，原码不会进入读取接口或审计日志

每个宾客身份只能认领一次。误领时，在主办方控制台的“宾客进度”中点击“重置”。

抽卡和任务提交都受当前婚礼环节约束，并由数据库事务强制执行：关闭注册后不再产生新抽卡；任务仅可在已开放的任务轮次提交。最终投票前，工作人员可在允许任务操作的环节完成延迟核验；环节已经关闭时只能按现场授权规则人工补记积分。终局公布后不能再核验或改分。旧实体卡兑换路径已经退役。

关闭注册不会锁住已经设置密码的宾客：名单只显示已有账号，宾客仍可在新手机或退出后使用原四位密码返回。未设置密码的姓名会暂时隐藏，也不能首次认领。

## 3. 部署到 Vercel

1. 将项目上传到 GitHub 私有仓库。
2. 在 Vercel 中导入仓库。
3. 添加与 `.env.local` 相同的四个环境变量。
4. 点击 Deploy。
5. 用最终网址生成普通二维码。

## 4. 替换成真实宾客

优先使用后台“宾客名单管理”中的批量新增：关闭注册后，每行粘贴“显示姓名 | 登录名 | 桌号”，核对预览并确认后一次导入。系统会拒绝重复登录名，任一行冲突时整批不写入，避免出现半份名单。

之后可在后台逐人补充长辈、仪式候选、桌号和工作人员备注。不要在 Supabase 中直接填写或分发宾客四位密码；密码由宾客首次登录时自行设置。

如需维护其他配置，可在 Supabase Table Editor 中查看：

- `guests`：姓名、登录名、组别、身份（密码哈希不可读取或手工设置）
- `tasks`：任务标题、描述、验证方式、分数、适用身份
- `assignments`：给某位宾客绑定某项任务
- `clues`：线索文本
- `guest_clues`：给指定宾客发放线索

婚礼当天优先使用主办方后台完成派任务、加分和发线索。直接编辑数据库只适合婚礼前批量准备数据，避免绕过审计记录。

不需要提前私发个人密码。宾客忘记密码时，主办方可在后台重置，由宾客重新设置。

## 开发验证

提交代码前运行：

```bash
npm run typecheck
npm test
npm run test:e2e
npm run build
```

`npm run test:e2e` 会在隔离的模拟数据上，以桌面和手机尺寸打开真实宾客页、主控台与主持人台；不会连接或改写生产数据库。Pull Request 也会自动运行这套浏览器彩排。

生产环境缺少 Supabase 配置或 12 位管理员密码时，服务器会拒绝启动相关功能。宾客和工作人员会话均使用随机令牌，数据库只保存不可逆哈希。不要在生产环境使用示例中的占位值。

主持人流程台会把最近一次成功同步的私密全员总览、流程与积分状态临时保存在当前浏览器标签页的 `sessionStorage` 中。短暂断网时仍可查看，但流程切换、计分和终局操作会被禁用；恢复网络后自动重新同步，也可手动点击“重新连接”。该缓存不会进入长期 `localStorage` 或 Service Worker，安全退出或工作人员会话失效时会被清除。

任务站也会把最近一次同步的宾客、任务和线索临时保存在当前标签页的 `sessionStorage` 中。断网时工作人员仍可按姓名查找并核对文字记录，但任务核验、派发、兑换、发线索和积分补记全部禁用；验证照片的短时链接可能需要联网。恢复网络后页面会自动同步，也可手动重连；安全退出或工作人员会话失效时会清除副本。

婚礼前准备、当天流程与故障恢复请参阅 [`docs/wedding-day-runbook.md`](docs/wedding-day-runbook.md)，现场角色可分别使用 [`docs/host-operator-guide.md`](docs/host-operator-guide.md) 和 [`docs/admin-operator-guide.md`](docs/admin-operator-guide.md)，人工验收项目请参阅 [`docs/acceptance-checklist.md`](docs/acceptance-checklist.md)。涉及数据库与应用同时升级时，必须按 [`docs/database-app-rollout.md`](docs/database-app-rollout.md) 的零写入维护与迁移顺序执行。主控首页的“婚礼日状态”会集中显示数据库连接、部署版本、当前流程、宾客进度和待处理数量；现场发现版本不一致时应先刷新，不要继续操作旧页面。

## 商业平台预览

`/platform` 与 `/platform/create` 是在现有婚礼系统之上增加的商业平台首期预览。它展示旗舰模板、单场买断与持续订阅两种交付方向，并允许客户在当前设备上组合视觉、叙事和游戏模块。

定制器草稿现阶段只保存在浏览器 `localStorage`，不会写入当前正式婚礼的 Supabase 数据库，也不包含账号、订单或付款功能。平台后续采用“客户项目控制层 + 单场婚礼隔离运行实例”的结构，避免不同婚礼共享宾客、隐藏身份、照片或积分数据。完整边界和开发顺序见 [`docs/platform-product-architecture.md`](docs/platform-product-architecture.md)。

## 当前 MVP 的边界

为了尽快、免费、稳定地上线，第一版没有加入：

- 视频上传、公共相册和原图长期归档
- 群聊
- 短信或微信登录
- 复杂动画

这些都可以在核心流程测试稳定后再加。

## 婚礼现场建议

- 婚礼前用至少 5 台不同手机测试。
- 准备纸质任务卡作为网络故障备用方案。
- 让主持人或伴郎伴娘负责后台审核。
- 最终投票开启后宾客页会自动刷新；主持人仍应现场口头提示。
- 公布身份前，后台会二次确认并自动关闭投票。
