# Wedding Task MVP

一个适合婚礼现场使用的轻量扫码网页：宾客先输入共享婚礼邀请码，从可搜索的名单中选择姓名，首次进入时自己设置四位密码；随后通过一次性抽卡领取组别、秘密身份和任务。主办方可以控制注册与婚礼阶段、重置密码、审核任务、加分、开放投票和公布结果。

## 已包含

- 宾客首次自设四位密码，之后可跨设备重新登录
- 一次性、均衡分组的秘密身份抽卡
- 默认隐藏身份卡，防止旁人看到屏幕
- 每位宾客只能读取自己的任务与线索
- 任务完成申请
- 宾客可附带完成说明；主办方或任务站核验时必须留下记录，审核通过后自动加分，退回原因会显示给宾客
- 宾客可选上传一张压缩后的验证照片；任务站也可在现场替宾客添加、更换或删除照片。照片保存在私有存储中，仅本人和已登录工作人员通过短时链接查看
- 按婚礼阶段开放多轮任务，未来轮次不会提前泄露
- 后台创建与派发任务、创建与发放私人线索
- 后台可编辑和停用任务、线索；每项任务都明确配置验证方式，并同步显示在宾客页、任务站和导出表中；任务派发后计分规则自动锁定，文字修正和停用仍会留下审计记录
- 线索可绑定具体间谍并分为三级；自动奖励优先发放与宾客本队间谍相关的线索，绑定信息不会进入宾客端或公开大屏
- 后台人工加减分与不可篡改的积分流水
- 后台预设未抽卡宾客的组别和秘密身份
- 后台可新增、编辑和停用宾客，维护桌号、长辈和仪式任务标记；停用会立即撤销会话且不会删除历史记录
- 四组八人容量控制；后台锁定的组别和身份会在抽卡时严格保留
- 内置首轮、升级、团队和隐藏任务库
- 正式任务清单确认前使用独立演示任务池，三种身份均可完整测试抽卡、提交和审核；切换正式模式后演示任务不会再被抽中
- 最终 32 人名单区分任务玩家、荣誉宾客和新人本人；所有人都可登录，荣誉宾客与新人看到专属卡片，固定仪式人员通过抽卡动画揭晓指定剧情任务
- 隐藏任务实体卡使用一次性兑换码：后台只显示原码一次，数据库仅保存散列，任务站兑换后自动锁定并派发到宾客手机
- 可配置一张一次性“隐藏间谍”任务卡；仅已抽卡的普通宾客可领取，审核通过后身份与积分原子生效，并在最终揭晓前保持私密
- 前 10 位完成首轮任务者自动获得升级任务，前 3 位额外获得 1 点个人积分和已配置线索
- 所有主办方修改写入操作审计记录
- 工作人员登录使用数据库中可撤销的哈希会话；后台、主持台和任务站均可安全退出共享设备
- 主办方密码连续输错五次后，服务端会按不可逆设备指纹暂停登录十五分钟；数据库不保存原始 IP、浏览器标识或尝试过的密码
- 最终投票与后台统计
- 最终投票按轮次隔离且每人每轮只能提交一次；公布身份时原子结算猜中间谍个人分、团队识破分和首轮完成率奖励
- 婚礼环节使用数据库状态机：后台不能从下拉框绕过投票轮次或终局结算；开启投票会自动关闭注册并清空大屏旧题目，切换常规环节也会关闭终局状态和旧倒计时
- 恶作剧者保留隐藏身份、伪装任务、同伴确认和最终揭晓，不设置独立恶作剧积分，也不参与额外的终局计分
- 投票开关和结果公布开关
- 可由后台单独开放的公开积分大屏，支持团队排名、个人榜与身份揭晓；投影端保留当前标签页最近同步副本并明确标注同步时间
- 主持人流程台内置每队初始 10 枚的丘比特金币钱包；竞拍扣减、返还和奖励均原子记账、禁止透支，并与团队积分严格分离
- 公开大屏严格分开个人积分和团队积分；个人任务分不会重复累加进团队排名
- 个人任务采用清晰的 1–3 分尺度：普通任务 1 分、升级和常规隐藏任务 2 分、隐藏间谍等特殊任务 3 分
- 主持题库内置十道已复核的常识题和六种可直接竞拍的资源效果；新人爱情故事题保持为待填写状态，避免用虚构答案进入正式流程
- 主办方后台提供服务端彩排预检：同时核对 32 人抽卡容量、三种身份任务池、四张隐藏卡代码、通用/专属线索、主持题目答案和四队竞拍钱包，未通过时明确列出阻塞项
- 彩排后可执行受保护的安全清场：必须先关闭所有公开入口、确认七类导出并输入固定确认词；系统保留配置和审计，原子清除运行数据并可重试清理私密验证照片
- 团队游戏 5/3/1 分独立流水、主持人控制的公开题目、规则、线索与大屏倒计时
- 独立主持人流程台：私密台词和正确答案与公开题目严格分离，支持题库编辑和一键发布
- 独立现场任务站：按姓名或组别快速查找宾客，现场补拍验证照片、核验任务、补派任务、发线索和调整积分，不显示秘密身份
- 最终奖项配置与公开颁奖区；奖项只有在单项发布且总结果公开后才会出现在大屏
- 投票、关闭和揭晓状态由数据库原子控制，避免投票开放时提前泄露结果
- 宾客页自动同步；弱网时可读取本次会话最近任务，恢复网络后自动刷新
- 首次联网访问后预缓存宾客应用壳和静态资源；断网刷新仍可打开任务页，API 与工作人员页面绝不进入离线缓存
- 公开大屏首次联网后也会准备离线页面壳；数据副本只保留在当前投影标签页，断网时显示 `CACHED` 和最近成功同步时间，不会把旧结果长期留在浏览器中
- 微信与刘海屏兼容：输入控件保持 16px 防止 iPhone 自动放大，页面跟随键盘可视高度，所有宾客和工作人员页面保留顶部、底部安全区；姓名页不会自动弹出键盘
- 切换到其他应用或锁屏时自动遮住秘密身份
- Supabase 云数据库
- 适合部署到 Vercel

## 1. 创建 Supabase 项目

1. 创建一个免费 Supabase 项目。
2. 打开 SQL Editor。
3. 新项目先运行 `supabase/schema.sql`。
4. 按文件名顺序运行 `supabase/migrations` 中尚未应用的迁移。迁移只允许向前执行，不要重复编辑已经上线的迁移文件。
5. 如需本地示例数据，再运行 `supabase/seed-example.sql`。它只创建可重复运行的测试宾客、首轮任务和线索；测试宾客仍需首次登录时自行设置四位密码，不能用于正式婚礼名单。
6. 在 Project Settings → API 中复制：
   - Project URL
   - `service_role` key

重要：`service_role` key 只能放在部署平台的服务器环境变量中，绝不能放进浏览器代码或公开仓库。

## 2. 本地运行

```bash
npm install
npm run dev
```

在项目根目录新建仅供本机使用、不会提交到 Git 的 `.env.local`：

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
ADMIN_PASSWORD=请填写至少12位的管理员密码
NEXT_PUBLIC_WEDDING_TITLE=我们的婚礼秘密任务
```

浏览：

- 首页：`http://localhost:3000`
- 宾客页：`http://localhost:3000/guest`
- 后台：`http://localhost:3000/admin`
- 主持人流程台：`http://localhost:3000/host`
- 现场任务站：`http://localhost:3000/station`
- 公开积分大屏：`http://localhost:3000/scoreboard`

登录流程：

- 初始示例邀请码：`LOVE2026`（仅用于本地启动；正式使用前必须在后台更换）
- 邀请码验证通过后才显示可搜索的宾客名单
- 可用中文、拼音或英文名搜索
- 首次选择姓名后自己设置并确认四位密码
- 以后选择相同姓名并输入原密码即可重新登录
- 四位密码只以哈希形式存储在 Supabase
- 同一设备和宾客连续输错五次后暂停登录十五分钟；限流记录只保存不可逆指纹，不保存原始 IP
- 后台可把公开示例邀请码轮换为正式共享码；数据库只保存 bcrypt 哈希，原码不会进入读取接口或审计日志

每个宾客身份只能认领一次。误领时，在主办方控制台的“宾客进度”中点击“重置”。

抽卡、任务提交和隐藏实体卡兑换都受当前婚礼环节约束，并由数据库事务强制执行：关闭注册后不再产生新抽卡；任务仅可在已开放的任务轮次提交；隐藏卡仅在第二轮任务或团队挑战兑换。工作人员仍可在任务站为现场延迟核验做审计化补录。

关闭注册不会锁住已经设置密码的宾客：名单只显示已有账号，宾客仍可在新手机或退出后使用原四位密码返回。未设置密码的姓名会暂时隐藏，也不能首次认领。

## 3. 部署到 Vercel

1. 将项目上传到 GitHub 私有仓库。
2. 在 Vercel 中导入仓库。
3. 添加与 `.env.local` 相同的四个环境变量。
4. 点击 Deploy。
5. 用最终网址生成普通二维码。

## 4. 替换成真实宾客

优先使用后台“宾客名单管理”中的批量新增：关闭注册后，每行粘贴“显示姓名 | 登录名 | 桌号”，核对预览并确认后一次导入。系统会拒绝重复登录名，任一行冲突时整批不写入，避免出现半份名单。

之后可在后台逐人补充长辈、仪式候选、桌号和工作人员备注。不要在 Supabase 中直接填写或分发宾客四位密码；密码由宾客首次登录时自行设置。

如需维护其他配置，可在 Supabase Table Editor 中查看：

- `guests`：姓名、登录名、组别、身份（密码哈希不可读取或手工设置）
- `tasks`：任务标题、描述、验证方式、分数、适用身份
- `assignments`：给某位宾客绑定某项任务
- `clues`：线索文本
- `guest_clues`：给指定宾客发放线索

婚礼当天优先使用主办方后台完成派任务、加分和发线索。直接编辑数据库只适合婚礼前批量准备数据，避免绕过审计记录。

不需要提前私发个人密码。宾客忘记密码时，主办方可在后台重置，由宾客重新设置。

## 开发验证

提交代码前运行：

```bash
npm run typecheck
npm test
npm run build
```

生产环境缺少 Supabase 配置或 12 位管理员密码时，服务器会拒绝启动相关功能。宾客和工作人员会话均使用随机令牌，数据库只保存不可逆哈希。不要在生产环境使用示例中的占位值。

主持人流程台会把最近一次成功同步的私密题目、台词和答案临时保存在当前浏览器标签页的 `sessionStorage` 中。短暂断网时仍可查看，但发布、计分和金币调整会被禁用；恢复网络后自动重新同步，也可手动点击“重新连接”。该缓存不会进入长期 `localStorage` 或 Service Worker，安全退出或工作人员会话失效时会被清除。

任务站也会把最近一次同步的宾客、任务和线索临时保存在当前标签页的 `sessionStorage` 中。断网时工作人员仍可按姓名查找并核对文字记录，但任务核验、派发、兑换、发线索和积分补记全部禁用；验证照片的短时链接可能需要联网。恢复网络后页面会自动同步，也可手动重连；安全退出或工作人员会话失效时会清除副本。

婚礼前准备、当天流程与故障恢复请参阅 [`docs/wedding-day-runbook.md`](docs/wedding-day-runbook.md)，人工验收项目请参阅 [`docs/acceptance-checklist.md`](docs/acceptance-checklist.md)。

## 当前 MVP 的边界

为了尽快、免费、稳定地上线，第一版没有加入：

- 视频上传、公共相册和原图长期归档
- 群聊
- 短信或微信登录
- 复杂动画

这些都可以在核心流程测试稳定后再加。

## 婚礼现场建议

- 婚礼前用至少 5 台不同手机测试。
- 准备纸质任务卡作为网络故障备用方案。
- 让主持人或伴郎伴娘负责后台审核。
- 最终投票开启后宾客页会自动刷新；主持人仍应现场口头提示。
- 公布身份前，后台会二次确认并自动关闭投票。
